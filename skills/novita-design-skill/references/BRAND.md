# Novita AI Brand Design Reference

Use this reference for visual direction, presentation style, and brand-safe design decisions.

## Brand Personality

Novita AI is an AI infrastructure brand. It should feel like a serious platform for builders, teams, and technical decision makers.

Primary traits:

- Clean
- Technical
- Trustworthy
- Fast
- Precise
- Modern
- Quietly confident

Secondary traits:

- Developer-friendly
- Data-aware
- Production-ready
- Efficient

Avoid:

- playful consumer-app styling
- crypto/neon aesthetics
- heavy purple-blue "AI" gradients
- cartoon mascots
- decorative bokeh/orb backgrounds
- vague futuristic chrome
- traditional corporate stock-design stiffness

## Visual Atmosphere

Novita's public design language is built on a warm near-white canvas, restrained contrast, and a single vivid green accent.

The brand should not look loud. It should feel engineered. Most of the screen is neutral; moments of action or proof get the green.

Use:

- `#FAFAFA` page canvas
- white cards
- near-black text
- alpha-based or light gray borders
- subtle shadows
- exact alignment
- technical labels in mono or mono-like styling
- real product or infrastructure references when available

Do not use large green page backgrounds by default. Green works best as CTA, active state, success mark, highlight, or tiny signal.

## Composition Principles

### Precision Grid

Align content to a clear grid. Let the whitespace do visible work. Use generous outer margins and moderate internal spacing.

For web and landing pages:

- constrain text width for readability;
- keep hero copy compact;
- align cards and data modules to consistent columns;
- use asymmetry only when it improves scanning.

For slides:

- one primary message per slide;
- no more than 3 to 5 supporting points;
- align all blocks to a shared grid;
- use green for the conclusion, key metric, or active step.

### Quiet Surfaces

Cards should feel present, not glossy. Use:

- white or `#F5F5F5` fills;
- `#E5E5E5`, `#D4D4D4`, or alpha borders;
- 4px, 6px, 8px, or 12px radius depending on scale;
- subtle shadows only when a layer truly floats.

Avoid thick borders, glassmorphism by default, heavy shadow stacks, and ornamental outlines.

### Technical Accent Layer

Add technical credibility through small details:

- mono labels;
- version tags;
- model/API-like cards;
- status chips;
- thin dividers;
- command-line snippets;
- aligned numbers;
- small chart axes;
- pipeline arrows;
- latency/throughput/quality metrics.

These details should support the message, not become decoration.

## Color Voice

Green means:

- start
- ready
- active
- success
- available
- selected
- primary action

Green does not mean:

- background texture
- generic decoration
- every icon
- every headline word
- whole-page mood

Use amber only for warning or occasional secondary CTA emphasis. Use blue for links, information, or neutral technical references. Use red only for errors or risk.

## Typography Voice

Use a geometric sans for most text. Miletus Grotesk Trial is preferred when available; Inter or TT Interfaces are acceptable public-safe fallbacks. Use a mono face for infrastructure tags, code, identifiers, or small technical labels.

Headline style:

- tight tracking at large sizes;
- medium or regular weight;
- direct phrasing;
- no ornamental ligature-heavy display fonts.

Body style:

- readable line height;
- high contrast;
- sentence case for descriptions;
- avoid unnecessary bolding.

Mono style:

- small labels;
- uppercase when used as an eyebrow or badge;
- positive tracking;
- never used for long paragraphs.

## Imagery And Illustration

Best imagery:

- real product screenshots when public-safe;
- abstract model cards;
- compute/inference pipelines;
- code and API snippets;
- latency, cost, throughput, or benchmark visuals;
- generated-media previews when relevant;
- clean diagrams over decorative scenes.

Avoid:

- vague robot imagery;
- human stock photos without a real use case;
- dark sci-fi dashboards;
- unrealistic holograms;
- generic "AI brain" visuals;
- dense server-room photos as background unless heavily justified.

## Voice For Copy

Use direct, technical, benefit-led language.

Good:

- "Run production AI workloads with lower latency."
- "One API for image, video, audio, and language models."
- "Scale inference without managing model infrastructure."

Avoid:

- "Revolutionize your creativity with magical AI."
- "Unlock limitless possibilities."
- "The future of intelligence is here."

Tone rules:

- concrete over hype;
- verbs over adjectives;
- proof over promise;
- short labels over marketing flourishes.

## Public-Safe Abstraction

When adapting internal source material:

- convert specific routes into generic "pages" or "sections";
- convert internal modules into user-facing capabilities;
- convert sidebar/navigation details into general navigation principles;
- convert component paths into generic UI primitives;
- convert domain-specific JSON into abstract workflows.

Do not reveal exact internal route structures, private IA, sidebar menu composition, internal file paths, or hidden product taxonomy.
